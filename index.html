Link format

  
Primary format — one URL parameter d with base64url-encoded JSON (UTF-8). No geometry, no full member lists: only the operations. The page fetches current objects from the OSM API and applies them.

  
{
  "comment": "Changeset comment",
  "changes": [
    {
      "type": "relation", "id": 175342, "version": 217,
      "add":    [{ "type": "relation", "id": 51805, "role": "subarea" }],
      "remove": [{ "type": "relation", "id": 51805, "role": "subarea" }],
      "tags":   { "name": "New name", "old_key": null }
    }
  ]
}

  
    
    
  • version is optional. If present and the live version differs, upload is blocked until you click Rebase (refetch + re-apply).
    • 
    
  • add entries already present (same type + id + role) are skipped with a note; remove entries not present produce a warning. Neither is fatal.
    • 
    
  • remove without a role matches any role for that type + id. tags value null deletes the tag.
    • 
    
  • Member operations only apply to relations. Tag operations apply to nodes, ways, and relations.
    • 
    
  • Upload is disabled when every computed object is unchanged (so re-opening an already-applied link cannot re-upload it).
    • 
    
  • View an existing changeset the same way: ?changeset=1234567, or paste an id/URL in the page header. After a successful upload the page switches to the new changeset's view automatically.
    • 
  

  
Simple format for a single relation (no JSON): ?rel=175342&v=217&add=rel:51805:subarea&comment=… — add/del may repeat; member spec is type:id[:role] with type n/w/r or node/way/relation. If both d and rel are present, d wins.
